Абилимпикс 2026 — рабочая последовательность
============================================

Редакция 1 ноября 2026. Альт 10.4 · OpenWrt 25.12.6 учебной VM · Ideco 23.4.40 · FreeIPA 4.9.14 · ZoneMinder 1.36.34 · Кибер Бэкап 18.6.

Порядок: устройство и место → действие/вставка → одна проверка. В SSH-сеансе смотрите приглашение: root@srv, root@r2 или локальный root@admin.

R2: копируйте по одной строке, без конечного Enter; затем нажимайте Enter вручную. Если вставка оборвалась или появилось >, Ctrl+C и повторить только эту команду. Для FRR сначала vtysh; uci вводится в обычной оболочке. На Альт блок <<'EOF' вставляется целиком до EOF.


Узел | Адрес и имя
R2 | r2.au-team.abi; ADMIN 172.16.120.1/24; PRINT 172.16.100.1/24; GRE 10.10.10.2/30
FW | fw.au-team.abi; CAM 172.16.10.1/24; SRV 172.16.110.254/24; GRE 10.10.10.1/30
WAN | DHCP; текущие примеры R2=192.0.2.10, FW=192.0.2.151
ADMIN | admin.au-team.abi, DHCP 172.16.120.10–200; текущий пример 172.16.120.86; шлюз/DNS 172.16.120.1; суффикс au-team.abi
SRV | srv.au-team.abi, 172.16.110.50/24, шлюз 172.16.110.254
CAM1 / CAM2 | cam1.au-team.abi=172.16.10.10; cam2.au-team.abi=172.16.10.20; /24, шлюз 172.16.10.1
PRINT | print.au-team.abi=172.16.100.100/24, шлюз 172.16.100.1
Домен и основная DNS-зона | au-team.abi; realm AU-TEAM.ABI; DNS-forwarder 77.88.8.8
Видео | video.au-team.abi A→172.16.110.50; http://video.au-team.abi/zm/
Панели | Ideco https://192.0.2.151:8443; Кибер Бэкап http://srv.au-team.abi:9877


Текущий DHCP-адрес ADMIN определять перед DNS-операциями; .86 — пример. Для LAN CAM/SRV используется /24, для GRE /30. Часовой пояс — Europe/Moscow.

120 минут: 0–8 обновление/порты R2 → 8–20 VLAN/DHCP/NAT → 20–32 FW/интернет → 32–47 GRE/OSPF → 47–72 FreeIPA/DNS/авторизация → 72–90 Кибер Бэкап → 90–109 камеры/видео → 109–116 печать → 116–120 проверки. Загрузки начать при появлении интернета; выполнять независимые этапы параллельно.

В новых иллюстрациях Ideco показана версия 23 текущего стенда. Снимки LuCI 25.12.6 относятся к отдельной тестовой VM 31 октября. Самостоятельную прошивку уже обновлённого R2 пропускайте. Для аппаратного ASUS нужен образ именно его модели, а не x86-образ учебной VM.

Все FQDN уточнены по таблице задания: *.au-team.abi. На прежних снимках могут оставаться старые имена; вводите имена из команд и таблицы этой редакции. Порядок установки FreeIPA рассчитан на чистый старт. Уже установленный сервер с прежним FQDN нельзя переименовывать простым повторением этих команд: потребуется отдельный перенос с учётом сертификатов и Kerberos.

R2 — сначала обновление, затем сеть
===================================

ADMIN → Firefox в Альт; команды R2 → SSH из терминала Альт. Рабочая версия форм — OpenWrt 25.12.6. Копируй по одной строке или короткому блоку; при оборванной вставке Ctrl+C, затем повтори только эту строку.

Единый домен всех устройств — au-team.abi; FQDN R2 — r2.au-team.abi. Старые имена, видимые на сохранённых снимках ниже, относятся к историческому состоянию. Новые значения бери из текста.


1. Обновление до настройки
--------------------------

R2 → SSH:


[БЛОК 001 | sh; место ввода указано перед блоком]
ubus call system board
cat /etc/openwrt_release
[КОНЕЦ БЛОКА 001]


Если учебная VM уже в 25.12.6 — прошивку пропусти. Для физического ASUS выбери точную модель/ревизию в Firmware Selector; учебная VM использует отдельную сборку со switch0.

ADMIN → Firefox → LuCI → System → Backup / Flash Firmware: скачать архив → выбрать подходящий sysupgrade → сверить SHA256/профиль → штатно записать → дождаться перезагрузки. Режим Keep settings выбирается по совместимости перехода и требованию чистого начала. Обновление выполняется до VLAN/DHCP/NAT.

Проверка: новая версия в Status → Overview. При расхождении прочитай /etc/openwrt_release.


2. Switch0
----------

Firefox → Network → Switch. Порты учебной модели: WAN 0, LAN 1–4, CPU 6. На аппаратном ASUS сопоставь номера с разъёмами по линку.


VLAN | CPU6 | WAN0 | LAN1 | LAN2 | LAN3 | LAN4
2 | tagged | untagged | off | off | off | off
100 | tagged | off | off | off | off | untagged
120 | tagged | off | untagged | off | off | off


Нажми Save; общее Apply — после адресов и DHCP.

[Скриншот: LuCI 25.12.6: матрица switch0; assets/image-9e8007589d809dc5b2.jpg]

Проверка: CPU tagged во всех трёх VLAN.

Firefox → Network → Interfaces → Devices → br-lan → Configure: Bridge ports = eth0.120.

[Скриншот: LuCI 25.12.6: выбрать eth0.120 в Bridge ports; assets/image-09a5ae0cfc332a118d.jpg]

[Скриншот: LuCI 25.12.6: параметры отдельного интерфейса PRINT; assets/image-35179f2cec4d2ceac0.jpg]

Проверка: PRINT не включён в br-lan.

DHCP Server → IPv4 Settings: DHCPv4 Service enabled, Start 10, Limit 191. Это диапазон .10–.200.

5. Обновить ADMIN
-----------------

ADMIN → локальный терминал root:


[БЛОК 002 | sh; место ввода указано перед блоком]
nmcli -f NAME,DEVICE con show --active
[КОНЕЦ БЛОКА 002]


Для фактического имени подключения из вывода; пример:


[БЛОК 003 | sh; место ввода указано перед блоком]

nmcli con up 'System enp6s18'
[КОНЕЦ БЛОКА 003]


Открой http://172.16.120.1.

Проверка: ip -4 addr show enp6s18 — адрес 172.16.120.10–200/24.

-------------

Firefox → Network → Firewall → Zones:


Зона | Networks | Input/Output/Forward | NAT
ADMINS | lan | ACCEPT/ACCEPT/ACCEPT | off
print | print | REJECT/ACCEPT/REJECT | off
wan | wan | REJECT/ACCEPT/REJECT | on


Разреши ADMINS → wan и ADMINS → print. В wan → Advanced Settings ограничь маскарадинг источником 172.16.120.0/24.

[Скриншот: LuCI 25.12.6: ограничение исходной сети NAT; assets/image-003d14f3ddc658c478.jpg]

Все пять снимков этой главы — сохранённые формы отдельной тестовой OpenWrt 25.12.6 от 31 октября. Имена на них исторические; правильное новое имя роутера — r2.au-team.abi. Расположение полей сохраняет смысл, значения проверяй на своём R2.

R2 → SSH, проверка:


[БЛОК 004 | sh; место ввода указано перед блоком]
fw4 check
[КОНЕЦ БЛОКА 004]



7. Имя и пакеты
---------------

R2 → SSH:


[БЛОК 005 | sh; место ввода указано перед блоком]
uci set system.@system[0].hostname='r2.au-team.abi'
uci commit system
hostname r2.au-team.abi
[КОНЕЦ БЛОКА 005]


Первое действие сохраняет имя в OpenWrt, последнее применяет его сейчас. Для локальных DHCP/DNS-имён:


[БЛОК 006 | sh; место ввода указано перед блоком]
uci set dhcp.@dnsmasq[0].domain='au-team.abi'
uci commit dhcp
/etc/init.d/dnsmasq reload
[КОНЕЦ БЛОКА 006]


Проверка: hostname возвращает r2.au-team.abi, а uci get dhcp.@dnsmasq[0].domain — au-team.abi. В этапе FreeIPA используется одна прямая зона; вторую зону и дублирующие forward/rebind не добавляй.


[БЛОК 007 | sh; место ввода указано перед блоком]
apk --version
ubus call network.interface.wan status
[КОНЕЦ БЛОКА 007]


Пакеты устанавливаются через apk; конкретные GRE/FRR пакеты — на этапе туннеля.

Проверка с ADMIN:


[БЛОК 008 | sh; место ввода указано перед блоком]
ping -c 3 -W 2 1.1.1.1
[КОНЕЦ БЛОКА 008]



8. После GRE — доступ к конечным устройствам
--------------------------------------------

Правило ADMINS-SRV разрешает только 172.16.120.0/24 → 172.16.110.50 через GRE. Оно не открывает камеры.

Для настройки камер из ADMIN добавь в R2 Traffic Rules отдельное ADMIN-CAM-WEB: Source ADMINS / 172.16.120.0/24, Destination GRE / 172.16.10.10 и 172.16.10.20, TCP 80 и 443, ACCEPT, IPv4. Для ping — отдельное правило ICMP echo-request с теми же адресами. На Ideco также разрешается нужный путь GRE → CAM.

Проверка: Firefox ADMIN открывает обе камеры по их фактическим адресам.

Быстрые шаги Ideco23 и GRE/OSPF
===============================


FW: WAN
-------

Место: локальное меню noVNC FW → управление сетевыми интерфейсами.

Действие: существующий порт провайдера → Ethernet → имя WAN → роль WAN → Системный контекст → DHCP → включить. В локальном меню управления сервером включить внешний веб-доступ. На ADMIN открыть Firefox → https://192.0.2.151:8443 (текущий WAN FW).

Проверка: панель доступна по WAN, версия 23.4.40.


FW: LAN
-------

Место: Firefox ADMIN → Ideco → Системный контекст → Сервисы → Сетевые интерфейсы → Интерфейсы Data Plane → Добавить → Ethernet.

Действие: CAM, роль LAN, 172.16.10.1/24, порт камер; SRV, роль LAN, 172.16.110.254/24, порт сервера. Включить и сохранить.

[Скриншот: Ideco23: где открыть WAN и CAM; assets/image-6e33fd8ba0dac57455.jpg]

1 ноября 2026: Интерфейсы Data Plane; в текущем стенде имена WAN, CAM, SRV и GRE-R2.

[Скриншот: Ideco23: поля WAN; assets/image-3378a79c7e96656e27.jpg]

1 ноября 2026: WAN → роль WAN, физический порт eth1_00 данного стенда, DHCP, автоматический MSS, интерфейс включён. Существующий порт сверяется по подключению.

Проверка: оба адреса и выбранные порты видны в списке.


FW: интернет
------------

Место: Firefox ADMIN → Ideco → SD-WAN → Next hop → Добавить.

Действие: ISP-WAN → интерфейс WAN → шлюз DHCP → сохранить. SD-WAN → Профили next hop → Системный профиль → вкладка Next hop → ISP-WAN → вернуться к настройкам профиля → Сохранить.

Проверка: системный профиль показывает рабочий ISP-WAN.


FW: DNS
-------

Место: Firefox ADMIN → Ideco → Сервисы → DNS → Внешние DNS-серверы → Добавить.

Действие: «Использовать DNS, выданные подключению» → WAN → Добавить.

[Скриншот: Ideco23: DNS от WAN; assets/image-1de56d8042eea9e280.jpg]

1 ноября 2026: Внешние DNS-серверы, строка «Выданные подключению»,192.0.2.1,WAN,включено.

Проверка: Управление сервером → Терминал:


[БЛОК 009 | sh; место ввода указано перед блоком]
getent ahostsv4 my.ideco.ru
[КОНЕЦ БЛОКА 009]



FW: лицензия
------------

Место: Firefox ADMIN → Ideco → Управление сервером → Лицензия.

Действие: зарегистрировать этот сервер через MY.IDECO, вернуться и обновить состояние лицензии.

Проверка: сервер зарегистрирован, лицензия действует.


FW: временный доступ SRV перед apt-get
--------------------------------------

Место: Firefox ADMIN → Ideco → Пользователи → Учётные записи → возле Все локальные значок Добавить пользователя.

Действие: имя SRV boot, логин setup-srv, пароль и подтверждение скрыто → Добавить. Пользователи → Авторизация → IP и MAC → Добавить: пользователь SRV boot, IP только 172.16.110.50, включено → Добавить. Административная роль не назначается.

Проверка: SRV → терминал:


[БЛОК 010 | sh; место ввода указано перед блоком]
curl -I --connect-timeout 10 --max-time 20 https://ftp.altlinux.org/
[КОНЕЦ БЛОКА 010]


У SRV boot → Сессии виден IP172.16.110.50. После успешного перехода на coduser старую привязку и сессию отключить, запись/историю сохранить.

Имена: srv.au-team.abi, admin.au-team.abi. Все устройства и FreeIPA используют одну DNS-зону au-team.abi. Realm: AU-TEAM.ABI. DNS-видеосервис: video.au-team.abi → 172.16.110.50.

13. Фильтры хранения7 и14 дней
------------------------------
